## ✨ Description du jeu

Hummm... ce TP semble *sussy*.

<center>![Aperçu du jeu](../../static/img/tp2/peintuerie.png)</center>

L'objectif du jeu est de peindre le plus de cases de notre couleur pendant 30 secondes. Avant une partie, on peut choisir une difficulté et combien de joueurs participeront :

<center>![Menu du jeu](../../static/img/tp2/menu.png)</center>

Après avoir choisi le nombre de joueurs, on peut voir les contrôles pour chaque joueur, lancer la partie ou annuler la partie.

<center>![Contrôles du jeu](../../static/img/tp2/controls.png)</center>

Les **flèches violettes** permettent de peindre une ligne complète. Les **fusées** permettent d'envoyer des projectiles dans 4 directions lorsqu'on appuie sur notre *touche rouge*. (Voir les contrôles plus haut)

<center>![Items du jeu](../../static/img/tp2/items.png)</center>

:::note

Bien entendu, initialement, il n'est pas possible de jouer. À mesure que vous compléterez les TODOs, le jeu deviendra fonctionnel.

Notez qu'il existe énormément de code déjà réalisé dans `extra.js`. Vous ne devez pas toucher à ce fichier, tout se passe dans `script.js`.

:::

### TODO 3

L'objectif de la fonction `decompte()` est de gérer l'évolution du **décompte** avant le début de la partie. Cette fonction sera appelée dans le **TODO 4**, une fois par seconde, 4 fois, et le résultat sera le suivant :

<center>![Todo 3](../../static/img/tp2/todo3_decompte.png)</center>

Selon la progression du décompte, on réalise des actions différentes dans `decompte()` :

Dans **tous les cas**, on diminue le décompte de 1 pour commencer. Puis :

* Lorsque le décompte atteint `2` ou `1`, on change seulement le nombre affiché dans la page.
* Lorsque le décompte atteint `0`, on affiche plutôt « Go ! ».
* Lorsque le décompte atteint `-1`, il y a quelques opérations :
  * On **cache** le décompte.
  * On indique, dans la bonne **variable globale**, que le partie devient active.
  * On appelle la fonction `launchGame()`. (Elle existe déjà, dans un autre fichier)
  * ⏳ On met fin au **planificateur** qui appelait `decompte()` une fois par seconde. (Lisez la boîte verte plus bas pour voir de quel planificateur on parle)

(Le fait de rendre la partie « active » fera rapidement apparaître des items dans l'arène. Le fait d'appeler `launchGame()` lancera un chrono qui démarre à `30` en bas du jeu)

:::tip

Pour **tester** cette fonction, étant donné qu'elle n'est pas appelée par un écouteur d'événements, voici comment procéder :

1. D'abord, exécutez ce code dans la console pour que le décompte soit affiché et ait sa valeur de départ :

```js
gDecompte = 3;
document.querySelector(".decompte").textContent = 3;
document.querySelector(".decompte").style.display = "block"; 
```

<center>![Todo 3](../../static/img/tp2/todo3_decompte_depart.png)</center>

2. Enfin, exécutez ce code dans la console, ce qui permettra d'appeler `decompte()` à toutes les secondes pour tester son comportement :

```js
gPlanifDecompte = setInterval(decompte, 1000);
```

Si vous n'avez pas bien **mis fin au planificateur** lorsque le décompte atteint `-1`, ces messages vont se répéter inutilement dans la console :

<center>![Todo 3](../../static/img/tp2/todo3_intervalle.png)</center>

Assurez-vous que ces messages n'apparaissent qu'une seule fois !

## 📐 Exigences supplémentaires

Si les exigences ci-dessous ne sont pas respectées, vous pourriez perdre des points dans des TODOs variés ou dans la catégorie « Pénalités » de la grille de correction.

Il est suggéré de commencer par faire le TP sans se soucier de ces exigences, puis de réviser son travail vers la fin pour respecter les exigences une fois que tout fonctionne bien.

#### 1. Ne pas oublier de point-virgule `;`

N'oubliez pas de conclure toutes vos instructions par `;`. Bien entendu, les **blocs** (if, while, etc.) se terminent par `}` et non par `;`.

#### 2. Soigner l'indentation du code

C'est-à-dire soigner l'alignement / l'espacement de vos lignes de code. N'oubliez donc pas de *spammer* `shift + alt + F`.

#### 3. Éviter le code répétitif

Si vous remarquez plusieurs lignes de code ultra similaires, optez pour des solutions comme :

* Une **boucle** pour le code qui se répète plusieurs lignes d'affilé.
* Une **fonction** qui reçoit de zéro à plusieurs paramètres pour les blocs de code qui se répètent dans plusieurs fonctions / endroits.

#### 4. Chaque nom de fonction ou de variable est approprié et représentatif

Vos noms de variables et de fonctions doivent être pertinents, bien représenter leur rôle et respecter les conventions de nommage vues au cours 2. Il est acceptable de nommer une variable `i` lorsque c'est pour parcourir une boucle, bien entendu.

#### 5. Jamais `document.querySelector()` plusieurs fois avec la même classe dans la même fonction

✅ Ceci est acceptable :

```js showLineNumbers
function maFonction(){

  document.querySelector(".patate").textContent = "Patate";
  document.querySelector(".bateau").style.color = "blue";
  document.querySelector(".poisson").style.width = "50px";

}
```

⛔ Ceci fait perdre des points ( `.patate` présente plusieurs fois ) :

```js showLineNumbers
function maFonction(){

  document.querySelector(".patate").textContent = "Patate";
  document.querySelector(".patate").style.color = "brown";
  document.querySelector(".patate").style.width = "50px";

}
```

✅ Ceci est bien :

```js showLineNumbers
function maFonction(){

  let patate = document.querySelector(".patate");

  patate.textContent = "Patate";
  patate.style.color = "brown";
  patate.style.width = "50px";

}
```
